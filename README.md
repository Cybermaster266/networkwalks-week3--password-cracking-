# Networkwalks Internship – Week 3: Password Cracking

## Project Overview

This repository documents my practical learning experience during Week 3 of my Cybersecurity Internship at Networkwalks.

The focus of this week's exercise was **Password Cracking and Hash Analysis**.

I explored how password hashes work and how password-cracking techniques can be used to recover passwords from hashes in an authorised testing environment.

## Project Objectives

- Understand the concept of password hashing.
- Learn how password hashes are used for storing credentials.
- Understand the basics of password cracking.
- Explore the John the Ripper password-cracking tool through its graphical interface, Johnny.
- Observe the password-cracking process.
- Understand the importance of strong passwords and secure password storage.

## Tools Used

### Johnny (John the Ripper GUI)

Johnny is a graphical user interface for John the Ripper.

It provides a visual way to interact with John the Ripper and perform password-cracking exercises.

During this practical session, I used Johnny to explore hash loading, password-cracking operations and the results.

## Practical Activities

### 1. Introduction to Password Hashing

Learned how passwords are transformed into hashes and why hashing is important in credential protection.

### 2. Hash Loading

Practised loading sample password hashes into Johnny for analysis.

### 3. Password Cracking

Used Johnny to perform a password-cracking exercise in an authorised learning environment.

### 4. Analysing Results

Observed the cracking process and examined the results to understand how password recovery works.

## Why Password Cracking Matters in Cybersecurity

Password cracking is an important subject in cybersecurity because it helps security professionals evaluate the strength of passwords and identify weaknesses in authentication security.

Understanding how password-cracking techniques work helps organisations improve their password policies, implement stronger authentication mechanisms and protect stored credentials.

It also highlights why passwords should be stored using secure, salted password-hashing algorithms rather than plaintext or fast general-purpose hashes.

## Security and Authorisation

No unauthorised systems or accounts were targeted.
